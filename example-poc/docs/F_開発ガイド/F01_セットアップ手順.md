# F01: セットアップ手順

## 1. 前提条件

| ツール | バージョン | 用途 |
|---|---|---|
| Node.js | 22.x | ランタイム |
| npm | 10.x | パッケージマネージャ |

Docker やデータベースは不要。

### RCDE 側の準備（3ステップ）

| ステップ | 内容 | 備考 |
|---|---|---|
| 1 | RCDE アカウント + 企業の作成 | https://rcde.jp で新規登録。初回ログイン時に企業作成を求められる |
| 2 | OAuth アプリケーションの登録 | 管理画面で作成し、Client ID / Client Secret を取得 |
| 3 | Redirect URI の登録（3-legged のみ） | `http://localhost:3000/api/auth/callback` を設定 |

> **現場（Construction）や契約項目（Contract）の手動作成は不要。** アプリ内で自動作成できる（後述）。

## 2. セットアップ手順

### 2.1 リポジトリのクローン

```bash
git clone https://github.com/i-Construction/rcde-frontend-sdk.git
cd rcde-frontend-sdk
```

### 2.2 SDK のビルド

```bash
npm install
npm run build
```

### 2.3 PoC プロジェクトのセットアップ

```bash
cd example-poc
npm install
```

### 2.4 環境変数の設定

```bash
cp .env.example .env
```

`.env` を編集:

```bash
# サーバーサイドのみ（ブラウザに露出しない）
RCDE_CLIENT_ID=取得したClient ID
RCDE_CLIENT_SECRET=取得したClient Secret
RCDE_API_BASE_URL=https://api.rcde.jp
AUTH_TYPE=2legged  # "2legged" or "3legged"

# クライアントサイド（ブラウザに公開）
NEXT_PUBLIC_RCDE_API_BASE_URL=https://api.rcde.jp
```

### 2.5 開発サーバーの起動

```bash
npm run dev
```

ブラウザで http://localhost:3000 を開く。

## 3. 初回利用時のテストデータ作成

2-legged 認証でログインした後、現場が存在しない場合は **「テストデータを作成」ボタン** が表示される。

このボタンをクリックすると、2-legged API 経由で以下が自動作成される:

1. **テスト現場**（Construction） -- 名前は日付入りで自動生成
2. **テスト契約**（Contract） -- 上記現場に紐づく

### なぜ手動作成が不要か

RCDE バックエンドの 2-legged API（`CreateForExternal2Legged`）は:

- 受注者メールアドレスの入力が不要（内部でダミーユーザーが自動設定される）
- 承認プロセスが自動で完了する（`approvedProcess` が即座に実行される）

そのため、Web UI で手動で現場・契約を作成し、受注者を招待して承認を待つ手順が丸ごと不要になる。

```
POST /api/setup
  └─ create2LeggedClient()
       ├─ client.createConstruction({ ... })
       └─ client.createContract({ constructionId, ... })
           └─ バックエンド側で自動承認
```

## 4. 環境変数

| 変数名 | サイド | 説明 |
|---|---|---|
| `RCDE_CLIENT_ID` | サーバー | RCDE OAuth Client ID |
| `RCDE_CLIENT_SECRET` | サーバー | RCDE OAuth Client Secret |
| `RCDE_API_BASE_URL` | サーバー | RCDE API ベース URL |
| `AUTH_TYPE` | サーバー | 認証方式（`2legged` or `3legged`） |
| `NEXT_PUBLIC_RCDE_API_BASE_URL` | クライアント | ブラウザから参照する RCDE API URL |

`NEXT_PUBLIC_` プレフィックスが付いた変数のみブラウザに公開される。`clientSecret` は絶対にこのプレフィックスを付けないこと。

## 5. トラブルシューティング

| 問題 | 解決策 |
|---|---|
| `Module not found: @i-con/frontend-sdk` | SDK ルートで `npm run build` を実行 |
| 認証エラー | `.env` の `RCDE_CLIENT_ID` / `RCDE_CLIENT_SECRET` を確認 |
| 「テストデータを作成」でエラー | 2-legged 認証でログインしていることを確認 |
| ビューアが表示されない | 現場・契約選択画面で正しい現場と契約を選択しているか確認 |
